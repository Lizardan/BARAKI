# GitHub Issues — трекинг задач

С **2026-08-25** задачи и подзадачи проекта ведутся в GitHub Issues (`Lizardan/BARAKI`).
`GameDesign/TODO.md` больше не содержит таблиц задач — только ссылки и лог.

- Мастер-issue дорожной карты: [#47 ROADMAP](https://github.com/Lizardan/BARAKI/issues/47)
- Открытые: `is:open label:todo-task`; закрытая история: `is:closed label:todo-task`

## Язык (критичное правило)

| Часть issue | Язык |
|-------------|------|
| Заголовок | **Русский** (+ ID-префикс) |
| Суть / описание для человека | **Русский** |
| Технический контекст, данные, пути к коду, acceptance для агента | **English** — секция `## Agent context (EN)` |

Принцип: всё, что читает пользователь — по-русски; всё, чем оперирует AI-агент
(контекст, ссылки на файлы/классы, технические детали) — в понятном агенту виде,
по умолчанию английский. Код, команды, пути — как есть.

## Структура issue

```markdown
[ID] Русский заголовок задачи

## Суть            — по-русски: что и зачем
## Правила/Ограничения — по-русски (если нужны)
## Acceptance criteria — чекбоксы - [ ], формулировки русские
## Agent context (EN)  — английский: design refs, code paths, gotchas
Refs / links           — GDD-файлы, wiki/rules/*, связанные issues
```

- **Заголовок всегда с ID-префиксом**: `[PRE-007]`, `[GATE-001]`, `[EA-001]`,
  `[CHAT-001]`. Новые задачи получают префикс своей фазы или новый осмысленный
  префикс (согласовать в мастер-issue).
- Подзадачи — чекбоксы внутри тела; большие работы дробятся на отдельные issues,
  связанные ссылками.
- Заблокированные — метка `blocked` + чекбокс-список блокеров в теле.

## Метки

| Метка | Смысл |
|-------|-------|
| `todo-task` | любая задача из бэклога |
| `phase/pre-race2` | фаза до расы #2 |
| `phase/gate` | playtest + checkup перед расой #2 |
| `phase/ea` | Early Access контент / инфраструктура |
| `roadmap` | мастер-issues обзорного уровня |
| `blocked` | ждёт другую задачу/фазу |
| `deferred` / `icebox` | отложено (группа «МОРОЗИЛКА» в панели) |

## Воркфлоу

1. **Новая задача** → создать issue по структуре выше; при необходимости добавить
   строку в мастер-issue #47 и лог `GameDesign/TODO.md`.
2. **Начало работы** → назначить себя, отметить в комментарии; работать по TDD
   (тесты → код → `run_tests` green).
3. **Коммиты** → по правилам корневого `AGENTS.md` (русский, повелительное
   наклонение); ссылку на issue допустимо добавлять в теле коммита (`(#N)`).
4. **Закрытие** → только когда все чекбоксы acceptance выполнены и тесты green;
   в закрывающем комментарии — краткая сводка (можно по-русски).
5. **История не переписывается**: закрытые issues не переоткрывать ради правки
   текста — новые вводные заводятся новым issue со ссылкой.

## Миграция TODO.md → Issues (2026-08-25)

Все задачи из старых таблиц TODO.md перенесены: открытые — открытыми, выполненные —
закрытыми с сохранением ID (`GDD-*`, `MVP-*`, `HERO-*`, `HUB-*`, `DIST-*`, `RES-*`,
`PRE-*`, `GATE-*`, `EA-*`, `CHAT-*`). Пуш консольных логов плейтеста в issues
удалён из дебаг-консоли — issues используются только под задачи.

## Что не кладём в issues

Логи консоли, дампы playtest-репортов, разовые вопросы без задачи — не для Issues.
Баги из playtest — отдельные issue по структуре выше (`[BUG-*]` префикс допустим).

## Запуск задачи в opencode (Cursor)

Связка «увидел issue → запустил сессию» живёт в Cursor:

| Часть | Где |
|-------|-----|
| Панель задач | иконка ▶ в левой панели Cursor (**BARAKI Задачи**): открытые задачи в **раскрывающихся группах по приоритету меток** — ГОРИТ (оранжевый огонь, `priority/critical`/`urgent`/`P0`) → ВЫСОКИЙ ПРИОРИТЕТ (зелёная стрелка вверх, `priority/high`/`P1`) → ПО ОЧЕРЕДИ (остальные) → НИЗКИЙ (`priority/low`) → МОРОЗИЛКА (значок архива, `deferred`/`icebox`) → ЗАБЛОКИРОВАНО (⏸ пауза, `blocked`; метку снимает агент/человек вручную — автоматического отслеживания блокеров нет) → **СДЕЛАННЫЕ — ЖДУТ АПРУВА** → **ПОСЛЕДНИЕ СЕССИИ** (5 последних сессий opencode). Жизненный цикл (v0.0.54, статус «прервана» удалён): **не начата** → **выполняется** (агент реально работает: активность в терминале < 60 с) → **ждёт апрува** (агент замолчал > 60 с / сессия закрыта любым способом — ⚠) → **закрыта** (✔ апрув). Открытие сессии (⇱) НЕ меняет статус — «выполняется» включается только от реальной активности агента. Дерево — плоский скан-список (v0.0.38, откат с webview-панели в v0.0.47 — нативный вид TreeView признан каноничным): задачи не раскрываются; строка = `#номер Название` + иконка статуса (спиннер выполняется / ⚠ ждёт апрува / ⏸ блок или морозилка / tier-иконки), справа серым прогресс чеклиста `✓ n/m`; наведение показывает тултип (статус + метки + «Суть»); клик открывает markdown-превью (см. «Полный вид задачи» ниже); инлайн-кнопки по статусу — не начата: ▶ ✕ · выполняется: ⇱ · ждёт апрува: ⇱ ✔ · все: 🏷; мастер-issue и подзадачи запускаются по отдельности, мастер закрывается последним |
| Метки задач | инлайн-кнопка 🏷 на любой задаче → quick pick со всеми метками репозитория (множественный выбор, выбранные = стоят); клик переключает; подтверждение через `gh issue edit --add-label / --remove-label` |
| Последние сессии | группа **ПОСЛЕДНИЕ СЕССИИ** внизу дерева задач (между задачами и «Новой задачей»): до 5 последних сессий opencode текущего проекта, отсортированных по дате обновления; иконка 💻, клик → `opencode --session <id>`; показывает относительное время («2 ч назад») |
| Сводка проекта | над списком задач: краткая сводка + рекомендация, генерируется через opencode после каждого изменения состава задач (новая/закрыта) |
| Кнопка запуска | расширение **BARAKI Task Launcher** (`Tooling/CursorTaskLauncher/`) или `Ctrl+Alt+Shift+T`; внутри задачи — кнопка «НАЧАТЬ ВЫПОЛНЕНИЕ В OPENCODE»; правый клик → «Запустить в opencode». Запуск: полноценный opencode TUI (`opencode --agent plan --prompt …`) с промтом в поле ввода, через 5 с расширение шлёт Enter — задача уходит сама. Не использовать `opencode run -i`: это минимальный режим со стримингом в консоль, а не оболочка TUI |
| Новая задача текстом | под списком задач вьюха **«Новая задача»** (webview): поле + кнопка «ОТКРЫТЬ В OPENCODE» (или Ctrl+Enter) — открывает opencode TUI с введённым текстом как промтом, тот же механизм автопередачи, что у задач; терминал `opencode задача`, состояние задач не трогает |
| Открыть сессию (⇱) | на задачах «в процессе» / «ждёт апрува» — inline-кнопка терминала рядом с ✕: живой терминал → просто фокус; после перезапуска Cursor — резолв id сессии (`opencode session list --format json`; точный id захватывается через 30 с после запуска задачи, фолбэк — матч по каталогу проекта + `#<num>`/ID-токену/словам заголовка с порогом) и запуск `opencode --session <id>` — без промта и без новой сессии. Задача при этом возвращается из «сделана/прервана» в «в процессе». Кнопки действий (v0.0.54) — в блоке «Новая задача» внизу панели, в одном ряду справа от «ОТКРЫТЬ В OPENCODE»: четыре квадратные ghost-кнопки **⇄** (восстановить все сессии) / **↩** (последняя сессия) / **✦** (анализ) / **↻** (обновить); подсказка Ctrl+Enter переехала в placeholder поля | Инструменты gh/opencode запускаются через shell-exec с кавычками (opencode на Windows — npm-шим `.cmd`, execFile без shell его не выполняет) |
| Лаунчер | `Tooling/Start-IssueTask.ps1 -Issue <N>` |
| Тестовые задачи | #48 (Тест 1) и #49 (Тест 2) — для проверки панели; агент создаёт/удаляет файл и закрывает issue |

Что делает скрипт: тянет issue через `gh` (открыт? не назначен?), собирает промпт
(заголовок + тело + правила workflow: acceptance → тесты → закрыть issue) и открывает
новое окно Windows Terminal с интерактивной сессией opencode (`opencode run --interactive`)
в корне проекта. Флаг `-PrintPrompt` показывает промпт без запуска; `-NoInteractive` —
одноразовый прогон. Закрытие issue — за агентом по правилам выше; статус виден в том же
сайдбаре Cursor.

Исходники extension: `Tooling/CursorTaskLauncher/` (`package.json` + `extension.js`,
без сборки). Установка/обновление: `npx @vscode/vsce package --allow-missing-repository`
в папке исходников, затем
`cursor --install-extension Tooling/CursorTaskLauncher/baraki-task-launcher-<X>.vsix`
и полный перезапуск Cursor. Ручное копирование папок в `~/.cursor/extensions/` не
использовать — расходится с реестром `extensions.json` и расширение отбрасывается.

### Восстановление сессий

При перезапуске Cursor вкладки терминалов (`opencode #N`, `BARAKI анализ`, `opencode last`)
восстанавливаются с мёртвыми shell-процессами. Расширение **не** делает автоматического
restore — VS Code не гарантирует готовности shell к моменту отправки команды.

Кнопка **⇄** (v0.0.54, первая справа от «ОТКРЫТЬ В OPENCODE») запускает ручное
восстановление: читает файлы `sessions()` / `running()`, создаёт **новые** терминалы
с `opencode --session <id>` (не ищет `vscode.window.terminals` — те мёртвые после рестарта).
Статус: `"[BARAKI] Восстановлено сессий: X из Y"` в статус-баре + лог в Output.

### Последние сессии

Группа **ПОСЛЕДНИЕ СЕССИИ** внизу дерева задач (между задачами и «Новой задачей»).
Показывает до 5 последних сессий opencode текущего проекта, отсортированных по дате
обновления. Источник: `opencode session list --format json --max-count 10`, фильтр
по `directory == root()`. Клик по сессии → `opencode --session <id>` в новом терминале.
Показывает относительное время («2 ч назад»). Группа появляется только если есть сессии.

### Изменение меток задачи

Инлайн-кнопка **🏷** на любой задаче → quick pick со всеми метками репозитория.
Множественный выбор: выбранные метки = стоят на задаче; клик переключает.
Подтверждение через `gh issue edit --add-label / --remove-label`.
