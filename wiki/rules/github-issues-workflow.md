# GitHub Issues — трекинг задач

С **2026-08-25** задачи ведутся в GitHub Issues (`Lizardan/BARAKI`).
`GameDesign/TODO.md` — порядок фаз и лог решений, не таблица задач.

- Открытые задачи: `is:open is:issue`
- Закрытая история: `is:closed is:issue`
- Карта фаз: `GameDesign/TODO.md` (PRE → GATE → EA)
- Старый индекс [#47 ROADMAP](https://github.com/Lizardan/BARAKI/issues/47) закрыт — не задача и не канон

## Где что лежит

| Вопрос | Где |
|--------|-----|
| Что делать сейчас | открытые GitHub Issues = панель UnioTasks |
| В каком порядке фазы | `GameDesign/TODO.md` (короткий канон) |
| Зачем так устроено | `GameDesign/` GDD + `wiki/rules/` |
| История | закрытые issues + лог в `TODO.md` |

Один открытый issue = одна работа, которую можно начать и закрыть.
Эпик (родитель + дети) — только если кусок реально дробится, не «вся игра в одном issue».

## Язык (критичное правило)

| Часть issue | Язык |
|-------------|------|
| Заголовок | **Русский** (+ ID-префикс) |
| Суть / описание для человека | **Русский** |
| Технический контекст, данные, пути к коду, acceptance для агента | **English** — секция `## Agent context (EN)` |

Принцип: всё, что читает пользователь — по-русски; всё, чем оперирует AI-агент
(контекст, ссылки на файлы/классы, технические детали) — в понятном агенту виде,
по умолчанию английский. Код, команды, пути — как есть.

## Структура issue

```markdown
[ID] Русский заголовок задачи

## Суть            — по-русски: что и зачем
## Правила/Ограничения — по-русски (если нужны)
## Acceptance criteria — чекбоксы - [ ], формулировки русские
## Agent context (EN)  — английский: design refs, code paths, gotchas
Refs / links           — GDD-файлы, wiki/rules/*, связанные issues
```

- **Заголовок всегда с ID-префиксом**: `[PRE-007]`, `[GATE-001]`, `[EA-001]`,
  `[CHAT-001]`. Новый префикс — согласовать и записать в `GameDesign/TODO.md`.
- Подзадачи — чекбоксы внутри тела; большие работы дробятся на отдельные issues,
  связанные ссылками. Родитель-эпик закрывается последним.
- Заблокированные — метка `blocked` + чекбокс-список блокеров в теле.

## Метки

Четыре оси, без пересечений. `todo-task` не ставить — Issues и есть трекер.

**Статус** (категория UnioTasks; на GitHub переключается вместе с панелью):

| Метка | Смысл |
|-------|-------|
| (нет) | очередь — ещё не начали |
| `status/doing` | выполняется (▶ / продолжили работу) |
| `status/review` | ждёт апрува (сессия opencode закрыта) |
| закрытый issue | готово |

`status/doing` и `status/review` взаимно исключают. Не ставить оба.

**Очередь-исключения:**

| Метка | Смысл |
|-------|-------|
| `blocked` | ждёт другую задачу/фазу |
| `deferred` | отложено |

**Приоритет** — не больше одной (`priority/critical` / `priority/high` / `priority/low`). Без неё — обычная очередь.

**Справочные** (в панели не группируют): `phase/pre-race2`, `phase/gate`, `phase/ea`, `bug`.

Не создавать короткие дубли `critical` / `high` / `low` — только `priority/*`.

## Воркфлоу

1. **Новая задача** → issue по структуре выше; при смене порядка фаз — строка в `GameDesign/TODO.md`.
2. **Начало работы** → UnioTasks ▶ ставит `status/doing` (то же видно на GitHub).
3. **Сессия закончена** → расширение ставит `status/review`.
4. **Коммиты** → по корневому `AGENTS.md`; ссылку на issue допустимо в теле (`(#N)`).
5. **Закрытие** → ✔ в панели после проверки; агент issue сам не закрывает.
6. **История не переписывается**: закрытые issues не переоткрывать ради правки
   текста — новые вводные заводятся новым issue со ссылкой.

## Миграция TODO.md → Issues (2026-08-25)

Все задачи из старых таблиц TODO.md перенесены: открытые — открытыми, выполненные —
закрытыми с сохранением ID (`GDD-*`, `MVP-*`, `HERO-*`, `HUB-*`, `DIST-*`, `RES-*`,
`PRE-*`, `GATE-*`, `EA-*`, `CHAT-*`). Пуш консольных логов плейтеста в issues
удалён из дебаг-консоли — issues используются только под задачи.

## Что не кладём в issues

Логи консоли, дампы playtest-репортов, разовые вопросы без задачи — не для Issues.
Баги из playtest — отдельные issue по структуре выше (`[BUG-*]` префикс допустим).

## UnioTasks (Cursor)

Категории панели читают метки GitHub, не локальный таймер:

1. `status/doing` → Выполняется (▶ ставит метку)
2. `status/review` → Ждут апрува (закрытие сессии opencode ставит метку)
3. дальше по `priority/*`, затем `blocked` / `deferred`
4. пустые группы скрыты; Refresh на тулбаре списка

Кнопки: очередь ▶ ✕ · doing ⇱ · review ⇱ ✔ · все 🏷 (канон меток, не все 23 дефолта GitHub).

Заведение из панели «Новая задача»: текст + приоритет → вкладка редактора с TUI opencode (`--agent plan`, модель `opencode/big-pickle`, промпт из `task-creation-prompt.md`). Агент может задать уточнения, потом `gh issue create`. Как кнопка ▶, только промпт заведения, не `--mini` и не `--auto`.

Клиент: расширение UnioTasks (исходники `Desktop/UnioTasks`, vsix на рабочем столе).
Скрипт без панели: `Tooling/Start-IssueTask.ps1 -Issue <N>`.
Агент **не** закрывает issue (`gh issue close`).
