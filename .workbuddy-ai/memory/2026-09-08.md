## Общий баг: заклинания кастовались одновременно (без очереди)
- Симптом от пользователя: «если не в КД — кастуются одновременно; должны кастоваться
  только по очереди, следующее — только после окончания анимации каста».
- Корень: `MatchCombatSystem.ApplyAbilityAnimLock` делал `return` когда
  `kind == AbilityAnimKind.None && AnimState == ""`, поэтому `CastLockRemainingSeconds`
  оставался 0 → `TickUnit` не блокировал новый каст → следующий слот кита кастовался
  на следующем тике. Все активные способности с непрописанной анимацией (в т.ч. новые
  заклинания Древних BlightingGaze/VoidDrain/RaiseDrowned, ветеранские KingsCommand/Aegis/
  Sanctuary/GreaterColossus) страдали от этого.
- Фикс (2 правки):
  1. `AbilityAnimRules.ResolveKind` — добавлены `BlightingGaze or VoidDrain or RaiseDrowned
     => AbilityAnimKind.Cast` (явная классификация заклинаний Древних → 1.5s staff-cast lock).
  2. `ApplyAbilityAnimLock` — убран early-return; теперь при `lockSeconds <= 0f`
     ставится `AbilityAnimRules.StaffCastClipSeconds` (1.5s). Это общая гарантия: любая
     активная способность, прошедшая через каст (а пассивы/ауры сюда НЕ попадают —
     `TryCastKitAbilities` фильтрует `def.IsActive`), получает минимальный cast-lock и
     не может перекастовываться каждый тик.
- Поведение: спеллы теперь строго последовательны; следующий каст — только после истечения
  `CastLockRemainingSeconds` предыдущего.
- Тесты: поправлен `FacelessSpellRulesTests.FacelessCaster_MagicLevel2_CastsVoidDrain_...`
  (Drain раньше ждался на следующем тике, теперь — после истечения каст-лока ~1.5s; тик
  заменён на цикл 15×0.1) + добавлен `FacelessCaster_SpellsCastSequentially_NotSimultaneously`
  (проверяет CastLock>0 после каста и что второй спелл не стартует, пока лок не истёк).
- **Верификация Compile/EditMode НЕ выполнена** (Unity Editor открыт, unityMCP без Trust) —
  статический разбор пройден: поле `CastLockRemainingSeconds` есть в `MatchUnitState`,
  `AbilityIds.*` доступны в `AbilityAnimRules`, ни один тест не ассертит `BehaviorState`
  для None-способности, single-cast ассерты ветеранских/билдинг-тестов не задеты.
- Статус: правка готова, ждёт Compile+EditMode (Trust unityMCP или ручной прогон в Unity).
